# Implementation Plan: Export de Procès-Verbal de Réunion

**Branch**: `008-pv-export` | **Date**: 2026-05-08 | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification from `/specs/008-pv-export/spec.md`

## Summary

SmartMeet doit permettre aux utilisateurs de télécharger le Procès-Verbal d'une réunion en 4 formats : **PDF**, **Word (.docx)**, **Excel (.xlsx)**, et **CSV** (actions uniquement). Le backend Symfony expose 4 nouveaux endpoints REST protégés par JWT, un `ExportService` génère les fichiers à la demande via `dompdf`, `phpoffice/phpword`, `phpoffice/phpspreadsheet` et PHP natif. Le frontend React remplace le stub `alert()` dans `ArchiveLibrary.jsx` par des appels API réels avec indicateur de chargement.

---

## Technical Context

**Language/Version**: PHP 8.2+ (Symfony 7.4), JavaScript/React 18 (Vite 5)  
**Primary Dependencies (new)**:
- `dompdf/dompdf` — PDF generation from HTML/CSS
- `phpoffice/phpword` — Word .docx generation
- `phpoffice/phpspreadsheet` — Excel .xlsx generation
- Native `fputcsv()` — CSV (no library)

**Storage**: PostgreSQL 15 (read-only for this feature — no schema changes)  
**Testing**: PHPUnit (backend unit tests for ExportService), Vitest (frontend download button)  
**Target Platform**: Linux/Windows server (dev: Windows PHP built-in server)  
**Performance Goals**: < 10 seconds per export (SC-001); PDF/Word for typical PV (< 50 KB text)  
**Constraints**: JWT auth on all endpoints; access mirrors PV consultation rights  
**Scale/Scope**: Per-request generation; single-user at a time; no caching layer needed

## Implementation Phases

### Phase 1 — Backend: Dependencies & DTO

1. Install 3 Composer packages: `dompdf/dompdf`, `phpoffice/phpword`, `phpoffice/phpspreadsheet`
2. Create `MeetingExportDto.php` — value object assembling all PV data from Meeting + Summary entities
3. Add null-safety: every field defaults to `"Non renseigné"` if empty (FR-012)

### Phase 2 — Backend: ExportService

Create `ExportService.php` with 4 methods:

| Method | Output | Library |
|--------|--------|---------|
| `generatePdf(MeetingExportDto): Response` | Inline PDF binary | dompdf + Twig |
| `generateWord(MeetingExportDto): Response` | Inline DOCX binary | PhpWord |
| `generateExcel(MeetingExportDto): Response` | Inline XLSX binary | PhpSpreadsheet |
| `generateCsv(MeetingExportDto): StreamedResponse` | Streamed CSV | fputcsv() |

Each method:
- Builds the file content from the DTO
- Returns a Symfony `BinaryFileResponse` or `StreamedResponse`
- Sets correct `Content-Type` and `Content-Disposition` headers
- Logs: `export.generated` with `{format, meetingId, durationMs}`

### Phase 3 — Backend: Twig PDF Template

Create `Backend/templates/export/pv.html.twig`:

```
┌─────────────────────────────────────────────┐
│  [LOGO SmartMeet]           PROCÈS-VERBAL   │

│  Titre:         {{ meeting.title }}          │
│  Date:          {{ meeting.date }}           │
│  Durée:         {{ meeting.duration }}       │

│  ACTIONS À MENER                            │
│  [Tableau: Responsable | Description | Échéance | Statut] │
└─────────────────────────────────────────────┘
```

### Phase 4 — Backend: ExportController

Create `ExportController.php`:
- Route: `GET /api/v1/meetings/{meetingId}/export/{format}`
- Validates `format` ∈ {pdf, word, excel, csv} → 400 if unknown
- Loads Meeting with Summary (eager join to avoid N+1)
- Checks soft-delete → 404
- Checks Summary exists + type = 'PV' → 422
- Checks user access via existing `MeetingService` pattern → 403
- Builds `MeetingExportDto` → delegates to `ExportService`

### Phase 5 — Frontend: ArchiveLibrary.jsx

- Add `downloadingId` state (tracks `"${meetingId}-${format}"`)
- Replace `alert()` stub with real `api.get(..., { responseType: 'blob' })` call
- Trigger browser download via temporary `<a>` element
- Show `<Loader2 className="animate-spin">` on active download button
- Disable button during active download to prevent double-clicks
- Show toast/alert on error (keep existing error pattern)

### Phase 6 — Tests

**Backend (PHPUnit)**:
- `ExportServiceTest` — unit tests for DTO assembly + each format generator with fixture data
- `ExportControllerTest` — integration tests: 200, 401, 403, 404, 422 responses

**Frontend (Vitest)**:
- Download button shows spinner during loading
- Download button triggers correct API call with right format path segment
